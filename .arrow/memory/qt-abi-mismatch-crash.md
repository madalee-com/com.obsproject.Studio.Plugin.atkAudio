# Flatpak Qt ABI mismatch crash

- what: atkAudio flatpak plugin (atkaudio-pluginforobs.so) segfaults ONLY inside OBS flatpak env, not native OBS. Crash in juce::Component::centreWithSize(int,int) on filter apply; deepest real caller juce_ResizableWindow.cpp:341 ResizableWindow::setBoundsConstrained; last lines of MainHostWindow::ctor (72-190). Garbage return frames #1=0x1a, #6=0x1 = ABI/vtable corruption signature.
- root cause: plugin JUCE compiles against SDK /usr/lib/qt6 Qt; OBS flatpak ships its OWN bundled Qt 6.11.1 (obs-deps rebuild). Two different Qt builds in one process -> JUCE Component ABI drift -> vtable corruption. Native works: plugin + OBS share same system Qt.

- DEFINITIVE VERSION (verified live 2025-08-23/2026-08-26 obs-deps assets, not inference): gdb's "Qt 6.11.1" is NOT the SDK drift source — it matches obsproject/obs-deps release **2026-08-26** which ships Qt **6.11.1** (modules/Core.json, Gui.json, Widgets.json, Network.json all `"version":"6.11.1"`). The newer asset is a WINDOWS prebuilt (.lib/.pdb/.prl, NO .so) — proves OBS bundles obs-deps' 6.11.1 build and there is NO Linux bundle to wire. Older release 2025-08-23 ships 6.8.3 (superseded). So target = build Qt **6.11.x** into flatpak /app, point plugin QT_DIR/CMAKE_PREFIX_PATH at it (NOT SDK /usr/lib/qt6) so find_package(Qt6) links the same obs-deps-built ABI OBS uses at runtime. SDK 25.08 ships its own divergent ~6.11.x build = the drift source.
- dead ends: config-opts (-DQt6_VERSION/-DCMAKE_PREFIX_PATH) cosmetic - upstream find_package(Qt6 Widgets Core REQUIRED) has NO VERSION inline, can't inject. obs-deps Qt6 wiring impossible - obsproject/obs-deps 2025-08-23 release ships ONLY macos + windows qt6 bundles (no Linux Qt6 anywhere).
